# ArchGuard

> **منصة حوكمة البنية البرمجية عبر السياسات ككود (Policy-as-Code)**: مراجعة طلبات السحب (Pull Requests) تلقائيًا بناءً على معايير هندسية محددة الإصدار، وحماية البنية البرمجية من التدهور، وتقديم توجيهات عملية مدعومة بشجرة القواعد المجردة (AST).

## ما هو ArchGuard؟

غالبًا ما تصبح توثيقات البنية البرمجية المحفوظة في صفحات Wiki أو Notion غير مواكبة للواقع، نظرًا لضيق وقت المطورين لمطابقة القواعد الثابتة يدويًا أثناء المراجعات السريعة للكود.

يعالج **ArchGuard** هذه الفجوة بتحويل المعايير الهندسية إلى فحوصات آلية مستمرة عبر GitHub Checks:

- **التحليل الثابت عبر AST**: توظيف واجهة برمجة مترجم TypeScript لإجراء فحص لغوي متعمق، وقياس حجم الدوال والفئات، وبناء مخططات الاستيراد بين الطبقات.
- **ملاحظات مدمجة داخل سطور PR**: توضيح المخالفات والأسباب الهندسية وتقديم مقترحات التصحيح البرمجية مباشرة على سطور التعديل.
- **مؤشر صحة البنية البرمجية (0 - 100)**: تقييم موضوعي لجودة طلب السحب مع إمكانية منع الدمج في حال وجود مخالفات حرجة.
- **دليل تفاعلي متكامل**: تكامل مباشر مع موقع Docusaurus يوضح فلسفة كل قاعدة وسبل معالجتها.
- **استثناءات تقنية مؤقتة**: إدارة الديون التقنية تعريفيًا في ملف `.archstandards/config.yaml` مع إلزامية بيان السبب وتاريخ الانتهاء.

## البنية الهندسية للنظام

```text
  المطور ينشئ أو يحدّث طلب سحب (PR)
               │
               ▼
   [ خادم ويب هوك Fastify ] ──── التحقق الآمن باستخدام HMAC-SHA256
               │
               ▼
    [ طبقة وسيط GitHub ] ─────── جلب الملفات المعدلة والفروقات (Octokit)
               │
               ▼
      [ محرك ArchGuard الأساسي ] ─ محللات AST ومصنف الملفات
               │
        ┌──────┴──────┐
        ▼             ▼
   [ 18 قاعدة ]  [ الاستثناءات ]
        │             │
        └──────┬──────┘
               ▼
     [ مجمع الملاحظات ] ──────── حساب الخصومات ودرجة صحة البنية
               │
               ▼
    [ واجهة GitHub Check Run ] ── التنبيهات المدمجة وتقرير Markdown الشامل
```

## دليل القواعد الـ 18 المضمنة

| المجال               | معرف القاعدة | الوصف القياسي                                                      | مستوى الخطورة |
| :------------------- | :----------- | :----------------------------------------------------------------- | :------------ |
| **البنية المعمارية** | `ARCH-001`   | يمنع استيراد طبقة المستودعات مباشرة في المتحكمات                   | `error`       |
|                      | `ARCH-002`   | تجنب وضع منطق أعمال معقد داخل دوال المتحكمات (>20 سطرًا)           | `warning`     |
|                      | `ARCH-003`   | يجب ألا تعتمد طبقة الخدمات على أطر عمل الويب (Express/Fastify)     | `error`       |
|                      | `ARCH-004`   | يحظر الاعتماد الدائري (Circular Dependencies) بين الوحدات          | `error`       |
| **معايير API**       | `API-001`    | إلزامية التحقق من صحة مدخلات الطلبات (Zod, Joi)                    | `warning`     |
|                      | `API-002`    | يجب تحديد برمجية وسيطة للحد من معدل الطلبات (Rate Limiting)        | `warning`     |
|                      | `API-003`    | نقاط إنشاء الموارد POST يجب أن ترجع الرمز HTTP 201 Created         | `warning`     |
|                      | `API-004`    | يجب أن تتبع استجابات الأخطاء الهيكل القياسي الموحد (RFC 7807)      | `info`        |
| **الاختبارات**       | `TEST-001`   | تتطلب ملفات الخدمات الجديدة ملف اختبارات وحدة موازٍ                | `error`       |
|                      | `TEST-002`   | تتطلب الدوال البرمجية الحساسة (>15 سطرًا) اختبارات مخصصة           | `warning`     |
|                      | `TEST-003`   | الحفاظ على نسبة تغطية اختبارات لا تقل عن 80% في المستودع           | `warning`     |
|                      | `TEST-004`   | يحظر تعطيل الاختبارات (`.skip`, `xit`) لتجاوز فحوصات CI            | `error`       |
| **الأمان**           | `SEC-001`    | يمنع تضمين مفاتيح API أو كلمات المرور داخل الكود البرمجي           | `error`       |
|                      | `SEC-002`    | يمنع تسجيل كلمات المرور والرموز السرية في ملفات السجلات            | `error`       |
|                      | `SEC-003`    | يجب أن تستخدم نصوص الاتصال بقواعد البيانات متغيرات البيئة          | `warning`     |
| **التسمية**          | `NAME-001`   | يجب تسمية الفئات والواجهات بنمط PascalCase                         | `info`        |
|                      | `NAME-002`   | يجب تسمية الدوال والطرق بنمط camelCase                             | `info`        |
|                      | `NAME-003`   | يجب أن تستخدم المتغيرات المنطقية بادئات تأكيدية (`is`/`has`/`can`) | `info`        |

## الأداء والاختبارات المرجعية

تمت القياسات بدقة على بيئة Node.js v22 باستخدام مؤقتات رقمية عالية الدقة (`performance.now()`):

| الاختبار المرجعي          | النطاق                               | القياس الفعلي                                  |
| :------------------------ | :----------------------------------- | :--------------------------------------------- |
| **سرعة محلل AST**         | ملفات صغيرة (~100 سطر)               | **55,558 سطر/ثانية** (متوسط 1.73 مللي ثانية)   |
| **سرعة محلل AST**         | ملفات كبيرة (~2,000 سطر)             | **145,214 سطر/ثانية** (متوسط 14.5 مللي ثانية)  |
| **سرعة محلل AST**         | ملفات ضخمة (~5,000 سطر)              | **136,134 سطر/ثانية** (متوسط 38.6 مللي ثانية)  |
| **زمن فحص القواعد**       | مطابقة التعابير النمطية / التكوينات  | **0.002 مللي ثانية** (حتى 493,827 عملية/ثانية) |
| **زمن فحص القواعد**       | المسح الكامل لشجرة AST               | **1.1 – 1.7 مللي ثانية**                       |
| **مسار فحص PR المتكامل**  | طلب سحب صغير (3 ملفات، 161 سطرًا)    | **11.39 مللي ثانية** (p95: 15.58 مللي ثانية)   |
| **مسار فحص PR المتكامل**  | مشروع متكامل (100 ملف، ~6,000 سطر)   | **298.44 مللي ثانية** (p95: 369.12 مللي ثانية) |
| **التحقق من HMAC للخطاف** | مقارنة مشفرة آمنة التوقيت في Fastify | **0.362 مللي ثانية** (2,760 طلب/ثانية)         |
| **دقة الاكتشاف (Recall)** | مجموعة اختبارات برمجية حقيقية        | **100.0%** (0 إنذارات خاطئة للكود النظيف)      |

## دليل البدء السريع

### المتطلبات الأساسية

- Node.js $\ge 20.0.0$
- pnpm $\ge 9.0.0$

### التثبيت والبناء

```bash
git clone https://github.com/Ashutosh-Yadav-256/ArchGuard.git
cd ArchGuard

pnpm install

pnpm build

pnpm test

pnpm benchmark
```

### التشغيل محليًا

```bash
pnpm --filter @archstandards/github-app start

pnpm --filter @archstandards/docs start
```

## ملف الإعدادات (`.archstandards/config.yaml`)

```yaml
version: "1.0"

rules:
  include:
    - "*"
  exclude:
    - "NAME-*"

policy:
  fail_on:
    - "error"
  warn_on:
    - "warning"

scoring:
  base: 100
  deductions:
    error: 15
    warning: 5
    info: 1

exceptions:
  - rule: "ARCH-001"
    path: "src/controllers/legacy-export.controller.ts"
    reason: "Direct query optimization required pending database migration."
    expires: "2026-12-31"
```
